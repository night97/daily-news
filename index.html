## 什么是智能体间通信？ 智能体间通信是一种标准化方法，让 AI 智能体能够发现彼此能力、委派任务，并针对大型、持续进行的多步骤任务交换上下文和数据。其目的在于让 AI 智能体自行协调，无需人工操作员在系统间来回传递工作负载，也不必强迫通用大语言模型（LLM）处理需要大量专业知识和并发活动、足以挤占其上下文窗口的工作负载。 ### 突破传统障碍的标准化协作 A2A 和 MCP 等开放标准有助于解决两个问题：资源孤岛，以及系统集成中的 M x N 瓶颈。 当你能将智能体配置为在特定子领域或工作范围内运行时，智能体式 AI 的效果最佳。这有助于将其上下文窗口保持在可控范围内。但这要求将它们彼此隔离，意味着要么依赖人工操作员促进系统间通信，要么依赖定制网络集成，而后者也会带来新的问题。 如果缺乏通用通信标准，M 个 AI 智能体需要通过 N 个点对点 API 连接外部资源，就会出现 M x N 问题。大规模管理 M x N 个脆弱集成很快将难以持续。 [...] AI 智能体是该方法的具体实现。它是由底层 AI 模型运行的独立软件系统，能够接收输入、推理和决策，并自主执行一项或多项任务。 Comparison: agentic AI is an approach; an AI agent is software that applies it. . ### 对话式 AI 与智能体式 AI 对话式 AI是一种专门针对提示词生成文本或语音回复的人工智能系统。例如，它可处理生成式对话、转写、情感匹配或信息检索。 智能体式 AI 可能包含对话能力，但其定义特征是决策、问题解决和工具执行能力。AI 智能体通常可执行确定性的系统操作，例如运行数据库查询或在日历系统中安排预约。独立的 对话式 AI 系统只会生成回复，不会执行这些操作；除非它被构建为可访问工具的智能体，例如 ElevenAgents 中的语音智能体。 Conversational AI responds; agentic AI makes decisions and acts through tools. ## A2A 协议与 MCP：AI 智能体如何连接和共享工具 [...] ### 模型上下文协议（MCP） MCP 是 Anthropic 为解决智能体式 AI 的 M x N 问题而开发的开放协议。它让 AI 智能体通过单一统一接口与外部工具和数据源交互。AI 智能体持续运行 MCP 客户端，按需查询所有已连接 MCP 服务器提供的服务和数据源目录。客户端必须向服务器进行身份验证，服务器仅会公开客户端获授权使用的服务。 当用户向智能体提交请求时，智能体会提取用户意图，并检查其训练数据及 MCP 目录，以确定完成请求的最佳方式。如果它判定需要访问某 MCP 服务器提供的工具或数据，就会向该服务器发送 JSON-RPC 请求；服务器返回响应后，AI 智能体将其处理并用于完成用户请求。 MCP workflow: catalog servers, authenticate, choose a tool, and send a JSON-RPC request. ### A2A 与 MCP：主要区别 A2A 和 MCP 解决不同问题，并不互相排斥。许多团队会在类似的 workflow 中同时使用两者。
